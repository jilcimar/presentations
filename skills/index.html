A dor

Quando o prompt vira processo, ele merece virar Skill.

Toda vez que repetimos o mesmo checklist, padrão ou passo a passo, estamos perdendo a chance de padronizar e reaproveitar.
3

Sinais de que vale criar uma Skill:

1
Você cola o mesmo prompt sempreReview, documentação, deploy, criação de testes, abertura de PR.
2
O processo tem passos fixosEntradas, validações, saída esperada e cuidados.
3
O time precisa do mesmo padrãoMenos variação e mais consistência entre projetos.
Explicar que Skill não é “mais um arquivo”. Ela representa transformar conhecimento tácito em workflow reutilizável.
Conceito

O que é uma Skill?

Uma Skill é uma pasta com um SKILL.md que adiciona instruções, conhecimento ou workflow ao Claude Code.

Invocação manual: /skill-nameInvocação automática via descrição

Na prática, ela funciona como:

✓
Receita de execuçãoPassos claros para o Claude seguir.
✓
Memória versionadaPadrões do time salvos no repositório ou na máquina.
✓
Comando reutilizávelVocê chama com /nome-da-skill quando precisar.
Fonte: Claude Code Docs — Skills
Ponto principal: o description é muito importante porque ajuda o Claude a decidir quando carregar automaticamente a Skill.
Para que servem

Skills são boas para tarefas repetíveis e com padrão de saída.

Review de código

Checar riscos, testes, logs, tratamento de erro, padrões do projeto e sugestões objetivas.

Documentação

Gerar ADR, README, issue, changelog, runbook ou documentação técnica no formato do time.

Deploy / release

Executar checklist, validar branch, rodar testes, gerar resumo e mapear riscos antes da entrega.

Use CLAUDE.md para

  • Regras gerais do projeto
  • Contexto de arquitetura
  • Padrões permanentes

Use Skill para

  • Workflow invocável
  • Passo a passo repetível
  • Saída esperada bem definida
Fonte: Claude Code Docs — Skills
Comparar com CLAUDE.md: CLAUDE.md é contexto geral; Skill é procedimento com gatilho claro.
Estrutura

A estrutura mínima é simples. A estrutura boa é organizada.

my-skill/
├── SKILL.md        # obrigatório
├── template.md     # modelo para preencher
├── examples/
│   └── sample.md   # exemplo de saída
└── scripts/
    └── validate.sh # script opcional

Regra prática

Mantenha o SKILL.md focado no essencial e mova materiais grandes para arquivos de apoio.

A própria documentação recomenda referenciar os arquivos de apoio dentro do SKILL.md para o Claude saber quando carregá-los.
Fonte: Claude Code Docs — Supporting files
Aqui vale mostrar que dá para começar com um arquivo só, mas evoluir para templates, exemplos e scripts.
SKILL.md

O arquivo principal tem metadados + instruções.

---
name: code-review
description: Revise mudanças de código e aponte riscos, testes ausentes e melhorias antes de abrir PR.
disable-model-invocation: false
allowed-tools: Read Grep Bash
---

## Objetivo
Revisar alterações com foco em segurança,
qualidade, legibilidade e testes.

## Contexto atual
!`git diff HEAD`

## Saída esperada
1. Resumo das mudanças
2. Riscos encontrados
3. Testes recomendados

Campos úteis

D
descriptionAjuda o Claude a decidir quando usar a Skill.
/
disable-model-invocationUse true para deixar a Skill apenas manual.
$
$ARGUMENTSPermite passar argumentos ao comando.
Fonte: Claude Code Docs — Frontmatter
Explicar o dynamic context injection: linhas com comando podem inserir informações atuais, como o diff do git.

Exemplo prático

Skill para revisar mudanças antes do PR

---
name: pr-review
description: Revise alterações antes de abrir Pull Request, verificando riscos, testes e clareza da implementação.
---

## Entrada
Leia o diff atual:
!`git diff HEAD`

## Revise procurando
- Bug potencial
- Falta de teste
- Código duplicado
- Logs sensíveis
- Quebra de contrato/API

## Responda com
1. Resumo técnico
2. Pontos de atenção
3. Checklist antes do PR

Resultado esperado

Em vez de pedir “revise meu código” toda vez, você usa:

/pr-review

E a revisão já sai no padrão que você definiu.

Transição para a prática: mostrar que o .sh automatiza a cópia para ~/.claude/skills e deixa fácil atualizar as skills.
install.sh

O script instala no diretório global do Claude Code

#!/usr/bin/env bash
set -euo pipefail

SKILLS_SOURCE="$(pwd)/skills"
SKILLS_TARGET="$HOME/.claude/skills"

mkdir -p "$SKILLS_TARGET"
rsync -av "$SKILLS_SOURCE/" "$SKILLS_TARGET/"

echo "Skills instaladas em: $SKILLS_TARGET"
